# PRD — 게시판 (Board) MVP

자프링(Spring Boot 4.0.6 / JDK 25) 기반 게시판. 회원이 글·댓글을 쓰고 서로 추천하며 글 조회수가 집계된다. 용어는 `CONTEXT.md` 글로서리를, 삭제 정책은 `docs/adr/0001-soft-delete-everywhere.md`를 따른다.

## Problem Statement

이용자가 글을 올리고, 댓글로 대화하고, 마음에 드는 글·댓글을 추천하며, 어떤 글이 많이 읽혔는지 알 수 있는 공간이 없다. 또한 글을 지웠을 때 거기 달린 대화 맥락이 통째로 사라지거나, 떠난 회원의 흔적이 깨져 보이면 읽는 사람이 혼란스럽다.

## Solution

회원가입·로그인 후 글과 댓글을 작성·수정·삭제하고, 글과 댓글을 1인 1회 토글로 추천하며, 글 조회수가 같은 방문자 기준 24시간 중복 없이 집계되는 서버 렌더링(Thymeleaf) 게시판을 제공한다. 삭제는 전면 소프트 삭제로, 삭제된 댓글은 자리표시로 대댓글 맥락을 보존하고 탈퇴 회원의 글·댓글은 "탈퇴한 회원" 작성자로 유지된다.

## User Stories

### 회원 / 인증
1. 방문자로서, username·password·nickname으로 회원가입하고 싶다. 그래야 글·댓글을 쓸 수 있다.
2. 방문자로서, 이미 쓰인 username으로는 가입이 거부되길 원한다. 그래야 로그인 식별자가 충돌하지 않는다.
3. 방문자로서, 이미 쓰인 nickname으로는 가입이 거부되길 원한다. 그래야 표시명이 겹치지 않는다.
4. 방문자로서, 탈퇴한 회원이 쓰던 username·nickname으로는 가입할 수 없길 원한다. 그래야 식별자가 재사용되지 않는다.
5. 회원으로서, username·password로 로그인하고 싶다. 그래야 내 이름으로 활동할 수 있다.
6. 회원으로서, 로그아웃하고 싶다. 그래야 공용 기기에서 세션을 닫을 수 있다.
7. 회원으로서, 내 정보 페이지에서 nickname을 변경하고 싶다. 그래야 표시명을 바꿀 수 있다.
8. 회원으로서, nickname 변경 시 다른 회원과 겹치면 거부되길 원한다. 그래야 유니크가 유지된다.
9. 회원으로서, 내 정보 페이지에서 password를 변경하고 싶다. 그래야 계정을 안전하게 유지한다.
10. 회원으로서, username은 변경할 수 없음을 분명히 알고 싶다. 그래야 로그인 식별자가 안정적이다.
11. 회원으로서, 비밀번호가 평문이 아니라 BCrypt로 저장되길 원한다. 그래야 유출 시에도 안전하다.
12. 회원으로서, 탈퇴할 수 있길 원한다. 그래야 서비스를 떠날 수 있다.
13. 회원으로서, 탈퇴 후에도 내 글·댓글은 "탈퇴한 회원" 작성자로 남길 원한다. 그래야 남은 대화 맥락이 깨지지 않는다.

### 글 (Post)
14. 회원으로서, 글을 작성하고 싶다. 그래야 내용을 공유할 수 있다.
15. 비로그인 방문자로서, 글 목록과 상세를 읽고 싶다. 그래야 가입 전에 내용을 볼 수 있다.
16. 방문자로서, 글 목록에서 삭제된 글은 보이지 않길 원한다. 그래야 유효한 글만 본다.
17. 작성자로서, 내 글을 수정하고 싶다. 그래야 오류를 고칠 수 있다.
18. 작성자로서, 내 글을 삭제하고 싶다. 그래야 더 이상 노출되지 않게 한다.
19. 회원으로서, 남의 글은 수정·삭제할 수 없길 원한다. 그래야 내 글이 보호된다.
20. ADMIN으로서, 어떤 글이든 수정·삭제할 수 있길 원한다. 그래야 부적절한 글을 관리한다.
21. 방문자로서, 삭제된 글 상세에 직접 접근해도 열리지 않길 원한다. 그래야 삭제가 일관되게 동작한다.
22. 방문자로서, 글 상세에서 작성자·작성일·조회수·추천수를 보고 싶다. 그래야 글의 맥락을 안다.

### 댓글 (Comment)
23. 회원으로서, 글에 댓글을 달고 싶다. 그래야 글에 반응할 수 있다.
24. 회원으로서, 댓글에 대댓글을 달고 싶다. 그래야 특정 댓글에 답할 수 있다.
25. 회원으로서, 대댓글에는 다시 댓글을 달 수 없길 원한다. 그래야 계층이 2단계로 단순하게 유지된다.
26. 작성자로서, 내 댓글을 수정하고 싶다. 그래야 표현을 고칠 수 있다.
27. 작성자로서, 내 댓글을 삭제하고 싶다. 그래야 내 발언을 거둘 수 있다.
28. 회원으로서, 남의 댓글은 수정·삭제할 수 없길 원한다. 그래야 내 댓글이 보호된다.
29. ADMIN으로서, 어떤 댓글이든 수정·삭제할 수 있길 원한다. 그래야 부적절한 댓글을 관리한다.
30. 방문자로서, 삭제된 댓글이 "삭제된 댓글입니다" 자리표시로 보이길 원한다. 그래야 달린 대댓글의 맥락을 잃지 않는다.
31. 방문자로서, 댓글 작성자와 작성일을 보고 싶다. 그래야 누가 언제 썼는지 안다.

### 추천 (Recommend)
32. 회원으로서, 글을 추천하고 싶다. 그래야 좋은 글에 호감을 표시한다.
33. 회원으로서, 이미 추천한 글을 다시 누르면 추천이 취소되길 원한다(토글). 그래야 마음을 바꿀 수 있다.
34. 회원으로서, 한 글에는 1회만 추천 집계되길 원한다. 그래야 추천수가 공정하다.
35. 회원으로서, 댓글도 같은 방식으로 추천·취소하고 싶다. 그래야 댓글에도 호감을 표시한다.
36. 회원으로서, 내가 쓴 글·댓글도 추천할 수 있길 원한다. 그래야 제약 없이 동작한다.
37. 비로그인 방문자로서, 추천을 누르면 로그인으로 유도되길 원한다. 그래야 누가 눌렀는지 기록된다.
38. 방문자로서, 글·댓글의 현재 추천수를 보고 싶다. 그래야 인기를 가늠한다.

### 조회수 (View count)
39. 방문자로서, 글을 열면 조회수가 1 증가하길 원한다. 그래야 읽힌 정도를 안다.
40. 방문자로서, 같은 글을 24시간 내 다시 열어도 조회수가 더 오르지 않길 원한다. 그래야 수치가 부풀지 않는다.
41. 방문자로서, 댓글에는 조회수가 없음을 알고 싶다. 그래야 개념이 명확하다.

### 초기 데이터
42. 개발자로서, 빈 DB로 처음 실행하면 회원 5·글 5·댓글 5 샘플이 생성되길 원한다. 그래야 바로 화면을 확인한다.
43. 개발자로서, 회원이 한 명이라도 있으면 샘플 생성이 건너뛰어지길 원한다. 그래야 데이터가 중복 생성되지 않는다.

## Implementation Decisions

### 프로젝트 골격
- 위치 `back/`, 빌드 Gradle Kotlin DSL, Spring Boot 4.0.6 / JDK 25.
- 루트 패키지 `com.back`, 메인 클래스 `com.back.BackApplication`(`@EnableJpaAuditing`).
- 의존성: DevTools, Lombok, Spring Data JPA, Validation, Spring Security, H2, Thymeleaf, thymeleaf-layout-dialect.
- 패키지 구성은 도메인별 + `com.back.global.*`(공통). 초기 데이터는 `com.back.global.initData.BaseInitData`.

### 영속성·트랜잭션
- 모든 엔티티는 작성일·수정일을 가진 `BaseEntity`를 상속(JPA Auditing).
- OSIV(Open Session In View) 비활성화.
- 트랜잭션 경계는 액션(서비스) 메서드 레벨 `@Transactional`.
- 프로파일: dev = `application.yml` + `application-dev.yml`, 파일 DB `./db_dev.mv.db`, `ddl-auto: update`, h2-console 사용. test = `application.yml` + `application-test.yml`, H2 인메모리, `ddl-auto: create`.

### 도메인 모델 (ADR-0001: 전면 소프트 삭제)
- **회원(Member)**: `username`(유니크, 불변), `nickname`(유니크, 변경 가능), `password`(BCrypt), `role`(USER/ADMIN), `deleted` 플래그. 탈퇴 = 소프트 삭제. username·nickname 유니크 제약은 소프트 삭제 레코드에도 적용되어 재사용 불가.
- **글(Post)**: 작성자(Member 참조), 제목·본문, `viewCount`, `deleted`. 추천수는 PostRecommend 집계.
- **댓글(Comment)**: 글 참조, 작성자, 본문, `parent`(다른 Comment, optional), `deleted`. 부모가 있는 댓글(대댓글)에는 다시 자식 댓글을 달 수 없도록 검증(계층 2단계 상한).
- **PostRecommend**: (Member, Post) 한 쌍당 1행. 존재 여부가 추천 상태, 행 수가 글 추천수.
- **CommentRecommend**: (Member, Comment) 한 쌍당 1행. 글 추천과 분리된 별도 엔티티.

### 권한
- Spring Security로 인증. 글·댓글 수정·삭제는 **작성자 본인 또는 ADMIN**만 허용(서비스 레벨 권한 검증).
- 글 목록·상세 읽기는 비로그인 허용. 작성·수정·삭제·추천·내 정보·탈퇴는 인증 필요.
- 추천을 비로그인으로 시도하면 로그인 페이지로 유도.

### 소프트 삭제 노출 규칙 (ADR-0001)
- 모든 조회·집계 쿼리는 `deleted = false`를 기본 필터로 적용.
- **삭제된 글**: 목록·상세에서 완전히 숨김(직접 접근도 불가/안 보임).
- **삭제된 댓글**: "삭제된 댓글입니다" 자리표시로 노출하여 대댓글 맥락 보존. 본문·추천 액션은 비활성.
- **탈퇴 회원**: 글·댓글 유지, 작성자명은 "탈퇴한 회원"으로 표시.

### 추천 (토글)
- 추천 액션은 해당 (회원, 대상) 행이 없으면 생성(+1 효과), 있으면 삭제(취소). 본인 대상 제한 없음.
- 추천수는 별도 카운터 컬럼 없이 추천 행 집계로 노출(MVP 기준).

### 조회수 (쿠키 24시간 중복제거)
- 글 상세 진입 시, 글별 쿠키(예: 해당 글 식별자 포함) 부재면 `viewCount` +1 후 24시간 만료 쿠키 설정. 쿠키 존재 시 증가 없음.
- 로그인 여부와 무관하게 쿠키 기준으로 판정. 댓글에는 조회수 개념 없음.

### 화면 (서버 렌더링, Thymeleaf + layout-dialect)
- 공통 레이아웃 1개 + 페이지 템플릿: 회원가입, 로그인, 내 정보(nickname·password 변경, 탈퇴), 글 목록, 글 상세(댓글·대댓글·추천·조회수 포함), 글 작성·수정.
- 스타일: Tailwind 4.x Play CDN + DaisyUI, Pretendard 웹폰트 동적 서브셋.

### 초기 데이터
- `BaseInitData`의 `baseInitDataApplicationRunner` 빈(`@Transactional`): 회원이 1명이라도 있으면 즉시 중단. 없으면 회원 5·글 5·댓글 5 생성.

## Testing Decisions

- **시임**: 단일 시임 — `@SpringBootTest` + MockMvc로 HTTP → 컨트롤러 → 서비스 → DB 전 구간을 test 프로파일(H2 인메모리, `ddl-auto: create`)에서 검증. 도메인 규칙도 이 시임을 통해 HTTP 동작으로 확인한다.
- **좋은 테스트 기준**: 구현 세부(메서드 호출·내부 상태)가 아니라 **외부로 관찰 가능한 동작**만 검증한다 — 응답 상태/리다이렉트, 렌더된 내용에 글·댓글·추천수·"삭제된 댓글입니다"·"탈퇴한 회원"이 보이는지, 권한 없는 수정·삭제가 거부되는지, 추천 토글 후 추천수 변화, 같은 쿠키 재조회 시 조회수 불변 등.
- **대상 흐름**: 회원가입(유니크 위반 포함)·로그인·내 정보 변경·탈퇴, 글 CRUD + 권한(본인/타인/ADMIN), 댓글·대댓글 CRUD + 대댓글에 댓글 금지, 글·댓글 추천 토글·본인 추천, 조회수 24시간 중복제거, 삭제글 숨김·삭제댓글 placeholder.
- **인증 표현**: 보안 통과는 Spring Security Test(`@WithMockUser` 또는 실제 로그인 폼 POST)로 구성. 비로그인 추천 시 로그인 유도 검증 포함.
- **선행 사례(prior art)**: 그린필드라 기존 테스트 없음 — 이 PRD의 첫 MockMvc 통합 테스트가 이후 테스트의 기준 패턴이 된다.

## Out of Scope

- REST/JSON API, SPA, 모바일 앱 (서버 렌더링 페이지만).
- 글·댓글 검색, 카테고리/태그, 첨부파일·이미지 업로드.
- 추천 외 반응(싫어요·이모지), 신고, 차단, 알림.
- 비밀번호 찾기/이메일 인증, 소셜 로그인, OAuth.
- 글 목록 정렬·페이징 정책의 세부(기본 최신순·단순 페이징 이상은 비범위).
- 추천/조회 갱신의 AJAX화 (기본은 폼 기반 동작; UI 구현 디테일은 구현 시 결정).
- ADMIN 전용 관리 페이지 (권한만 적용, 별도 관리 화면 없음).

## Further Notes

- 용어는 반드시 `CONTEXT.md`를 따른다: 회원/username/nickname/ROLE/탈퇴, 글/댓글/대댓글/작성자/삭제된 댓글(placeholder), 추천/추천수/조회수. "좋아요·유저·게시물" 등 회피 용어를 쓰지 않는다.
- 삭제·탈퇴 정책 변경은 ADR-0001에 영향을 주므로, 정책을 바꾸려면 ADR을 먼저 갱신한다.
- 추천수를 행 집계로 둘지 카운터 컬럼으로 비정규화할지는 성능 이슈가 실제로 보일 때 재검토(현재는 집계).
